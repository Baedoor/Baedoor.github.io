On Airship Guard

Setting up labels

Main bot's feature is setting up custom labels, which can hold messages and attachments, and be later evoked. There is separate pool of labels for every server and user.

Labels can be set, updated and deleted. Initially, only the server owner has permission to do it, however they can expand the permissions to other roles (see next section).

To set a label, you use !set [label] [message] command. Label must be word that does not use space (so instead of test label, you'd need to use test_label or testlabel) and not be in list of "restricted labels" used by the bot itself (such as !set itself).
Once label is set, you can evoke it through ![label] message.
Example workflow below:

=== User
!set example
Hello!

=== Bot
The tag -example- was set!

=== User
!example

=== Bot
Hello!

Message for the label can be set both by separating it from the label via space or enter. Evoked label can be followed similarly by more text, e.g. !example something will still evoke label !example (if it exists).

Once label is set, you can update it with new contents through !update [label] [message]. It works the same way as setting, except it allows you to do it without deleting and making the label again. Update contents will replace the old ones entirely.

Labels can be deleted as well. For that, simply use !delete [label]. This will remove the label from the server.

To check what labels are set on the server, you can use !alllabels command. Bot will then DM you with list of labels for the server this message was used in.

Managing permissions

Initially, only server owner has permission to set, update and delete labels. That said, it is entirely possible to expand the permissions over to other roles.

To do that, use !admin perms add [tier] [role] command. To explain two modular segments:

Tier

Permissions are split between tiers, to allow better control over what certain role is able to do. There are currently two tiers:

  • high - high tier can set and delete labels
  • medium - medium tier can update labels

Tier lists are exclusive, which means that having high permissions do not grant you automatically ability to use permissions from medium level. It is not impossible these permissions will get expanded further for better control, or be role-driven instead of tier-driven (as currently).

Role

Role is simply a name of a role on the server - bot will search for it and get its unique ID. This means that after setting the role, its name can be changed without need to update the bot.
That said, this also yields small limitation that is - if the name is used by multiple roles, only the one first found by the bot will be used. The possibility of this to be an issue is negligible, but this will be addressed in the future.

Similarly to labels, you can also remove roles from the permissions. For that, simply use a command !admin perms remove [tier] [role].

You can also check for permissions by using command !admin perms check [tier].

Private labels

Unlike Project Tamriel's bot from which the idea of labels came, Airship Guard also allows users to have separate DM-based labels.
The whole concept works the same way as server labels, except private ones need to be set/updated/deleted through DMing the bot. Similarly, !alllabels used in DMs will list you private labels you set through DMs.

Miscellaneous features

Aside of labels, there is small list of misc features Airship Guard can be useful for.

  • !dice [n] - rolls the dice with [n] pipes, yielding you the result; can be useful
              for roleplaying purposes

Availability & Safety

Airship Guard is currently hosted locally, meaning its availability varies heavily depending on host's computer being turned on.
This will change in the future, as the plan for the bot is to be rehosted on either some purchased server or separate device. It is not possible currently, however, meaning the bot will not run 24/7, and can have entire days of being unavailable.

Additionally, the list of labels - due to how bot is currently hosted - is managed locally and coordinated through (private) GitHub repository. This won't be needed when the hosting shifts, but as long as the current system is held, it is recommended to not post any particularly personal or sensitive contents until this changes.

To keep yourself up-to-date on Airship Guard development, feel free to join the server.
